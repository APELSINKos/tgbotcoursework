## 1. Введение

«Личный помощник» — Telegram-бот, который собирает в одном чате повседневные мелочи: погоду с практическими советами, напоминания, заметки, трекер привычек и курсы валют. Отличие от обычных ботов-справочников — проактивность: каждое утро бот сам присылает сводку на день.

Область применения — личная организация дня. Целевая аудитория — пользователи Telegram, которым неудобно держать под эти задачи несколько отдельных приложений. Бот рассчитан на личные чаты; работа в группах не предусмотрена.

## 2. Основания для разработки

Разработка ведётся в рамках практической работы №1 «Тестирование программного продукта методом „чёрного ящика“» по дисциплине «Тестирование, верификация и валидация программного обеспечения».

Исходные и нормативные документы:

- методические указания по выполнению практических работ по дисциплине;
- задание на практическую работу №1;
- ГОСТ 19.201-78 «Техническое задание. Требования к содержанию и оформлению»;
- ГОСТ 34.602-2020 «Техническое задание на создание автоматизированной системы»;
- ISO/IEC/IEEE 29148:2018 «Системная и программная инженерия — Процессы инженерии требований»;
- документация Telegram Bot API, Open-Meteo API, сервиса курсов ЦБ РФ.

## 3. Назначение разработки

Бот должен решать следующие задачи:

1. Сократить время на утреннее планирование: одно сообщение вместо проверки погоды, календаря и списка дел в разных приложениях.
2. Переводить прогноз погоды из цифр в решения: брать ли зонт, как одеться, подходит ли день для велосипеда.
3. Не давать забывать о делах — напоминать в заданное время без участия пользователя.
4. Помогать вырабатывать привычки за счёт ежедневных отметок и наглядной серии.
5. Давать актуальный официальный курс доллара и евро и пересчитывать суммы.

## 4. Требования к программе

### 4.1. Функциональные требования

Функции сгруппированы по разделам главного меню. Разделы связаны между собой следующим образом:

- город, выбранный в настройках, определяет прогноз в разделе «Погода» и часовой пояс, по которому считаются напоминания, отметки привычек, «Мой день» и утренняя сводка;
- раздел «Мой день» собирает данные остальных разделов: погоду, напоминания на сегодня, прогресс привычек и количество заметок;
- утренняя сводка строится из тех же данных, что и «Мой день», и отправляется тем же фоновым процессом, который рассылает напоминания;
- раздел «Курс валют» не зависит от остальных разделов.

Правила советов (FR-12):

| Условие | Совет |
|---|---|
| Сейчас осадки ≥ 0,1 мм | «🌧 Сейчас идёт дождь — возьми зонт» |
| Осадки ≥ 0,1 мм начнутся в ближайшие 120 минут | «🌧 Через N минут дождь — возьми зонт» |
| Осадков в ближайшие 2 часа нет, но позже сегодня вероятность ≥ 60% | «☔ Дождь ожидается после ЧЧ:00 — зонт сегодня пригодится» |
| Температура в 18:00 выше, чем в 08:00, на 5 °C и более | «🧥 Утром холодно, вечером потеплеет» |
| Температура в 18:00 ниже, чем в 08:00, на 5 °C и более | «🌡 К вечеру похолодает — захвати кофту» |
| Ветер ≥ 10 м/с | «💨 Сильный ветер — одевайся плотнее» |
| Ощущаемая температура ≤ −15 °C | «🥶 Очень холодно — одевайся теплее» |
| Ощущаемая температура ≥ +30 °C | «🥵 Жара — пей больше воды» |
| Осадков сегодня не ожидается, дневной максимум от +12 до +28 °C, ветер < 7 м/с | «🚲 Сегодня хороший день для велосипеда» |

При текущей температуре 0 °C и ниже вместо слова «дождь» используется «снег», значок 🌨, а совет про зонт заменяется на «надень капюшон».

### 4.2. Требования к надёжности

| ID | Требование |
|---|---|
| NFR-01 | Недоступность внешних сервисов (погода, курсы, поиск городов) не приводит к остановке бота; пользователь получает понятное сообщение. Время ожидания ответа внешнего сервиса — не более 10 секунд. |
| NFR-02 | Ошибка в фоновой проверке напоминаний не останавливает ни фоновый поток, ни обработку сообщений. |
| NFR-03 | Данные хранятся в файле `bot.db` и сохраняются при перезапуске. Напоминания, время которых наступило, пока бот был выключен, отправляются после запуска. |
| NFR-04 | Некорректный пользовательский ввод любого вида не приводит к аварийному завершению и не оставляет бота в состоянии ожидания без подсказки. |
| NFR-05 | Если пользователь заблокировал бота, неотправленное напоминание помечается отправленным и не блокирует остальные. |

### 4.3. Условия эксплуатации

- Компьютер или сервер с постоянным доступом в интернет.
- Python 3.10 или новее.
- Доступ к `api.telegram.org`, `api.open-meteo.com`, `geocoding-api.open-meteo.com`, `www.cbr-xml-daily.ru`.
- Одновременно с одним токеном должен работать только один экземпляр бота.
- Ответ на нажатие кнопки без обращения к внешним сервисам — не более 3 секунд, с обращением — не более 12 секунд.

### 4.4. Требования к совместимости

- Серверная часть: Windows 10/11, Linux, macOS.
- Клиентская часть: любые официальные клиенты Telegram (Android, iOS, Desktop, Web).
- Библиотеки: pyTelegramBotAPI 4.36, requests 2.34, python-dotenv 1.2, tzdata.
- Язык интерфейса — русский.

- UI-05. После нажатия кнопки под сообщением индикатор загрузки на ней исчезает.
- UI-06. Названия разделов в приветствии, в меню и в документации совпадают.

## 6. Критерии приёмки

1. Реализованы все функциональные требования раздела 4.1.
2. Успешно выполнено не менее 95% тест-кейсов приёмочного набора; среди невыполненных нет тест-кейсов высокого приоритета.
3. Отсутствуют дефекты критической серьёзности: аварийное завершение, потеря или смешение данных пользователей, утечка токена.
4. Бот доступен команде-тестировщику способом, описанным в разделе 7.
5. В репозитории отсутствуют токен и файл базы данных.
6. Предоставлена документация из раздела 7.

## 7. Требования к документации и запуск

Вместе с продуктом предоставляются:

- `README.md` — обзор и быстрый старт;
- `docs/TZ.md` — настоящее техническое задание;
- `docs/USER_GUIDE.md` — руководство пользователя;
- `docs/ARCHITECTURE.md` — описание архитектуры со схемами;
- `docs/DEPLOY.md` — развёртывание на сервере и управление службой.

**Запуск продукта.** Команде-тестировщику продукт предоставляется в виде работающего бота [@ikbo63_24_bot](https://t.me/ikbo63_24_bot): достаточно открыть его в Telegram и нажать **Start**. Бот развёрнут на сервере и доступен круглосуточно, установка на стороне тестировщика не требуется.

Для локального запуска нужен Python 3.10 или новее: установить зависимости командой `pip install -r requirements.txt`, задать токен бота в переменной `BOT_TOKEN` и выполнить `python bot.py`. В консоли появится `Bot is running. Press Ctrl+C to stop.` База данных `bot.db` создаётся автоматически при первом запуске.

Для проверки утренней сводки без ожидания утра: в настройках задать время сводки на 1–2 минуты раньше текущего — сводка придёт в течение минуты. Это сработает, только если сегодня сводка ещё не приходила: она отправляется один раз в сутки.

## 8. Порядок контроля и приёмки

Контроль проводится методом «чёрного ящика»: проверяется соответствие поведения бота требованиям без анализа исходного кода.

| Вид проверки | Что проверяется | Техники |
|---|---|---|
| Функциональное тестирование | Требования FR-01…FR-74 | Эквивалентное разбиение, тестирование вариантов использования |
| Проверка границ | Длины текстов (200, 500, 50), лимиты количества (20, 50, 10), время (23:59 / 24:00), сумма (0 / 1 000 000 000), серия (2 / 3 дня) | Анализ граничных значений |
| Негативное тестирование | Пустой ввод, пробелы, спецсимволы, очень длинные строки, стикеры и фото вместо текста, несуществующие даты и города | Error guessing |
| Тестирование состояний | Диалоги ввода: отмена, команда посреди ввода, повторный ввод после ошибки | Тестирование переходов состояний |
| Тестирование интерфейса | Требования UI-01…UI-06, тексты кнопок и сообщений | Чек-лист |
| Тестирование надёжности | NFR-01…NFR-05: перезапуск, отключение сети | Исследовательское тестирование |
| Тестирование документации | Полнота и соответствие документации продукту | Ревью, чек-лист |

Приёмочные испытания проводит команда-тестировщик. Результаты оформляются тест-кейсами со статусами Passed / Failed / Blocked / Not Run и отчётами о дефектах с классификацией по серьёзности: критическая, средняя, незначительная. Продукт считается принятым при выполнении критериев раздела 6.
